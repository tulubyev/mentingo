# Оплата курсов через ЮKassa

Функция позволяет продавать курсы LMS (lms.wiki) с оплатой в рублях через ЮKassa: студент нажимает
«Купить», при желании вводит промокод, оплачивает на странице ЮKassa (карта, СБП, SberPay и т. д.)
и после подтверждения оплаты автоматически записывается на курс. Stripe в коде остаётся, но
отключён (нет ключей); ЮKassa работает параллельно и имеет приоритет, если заданы её ключи.

## Что сделано

**API (`apps/api/src/payments`)**

| Метод и путь                                                      | Доступ                                | Назначение                                                                                 |
| ----------------------------------------------------------------- | ------------------------------------- | ------------------------------------------------------------------------------------------ |
| `GET /api/payments/config`                                        | публичный                             | `{ provider: "yookassa" \| "stripe" \| null, currency }` — какой провайдер включён         |
| `POST /api/payments/yookassa/quote`                               | `billing.checkout`                    | `{ courseId, promoCode? }` → итоговая цена с учётом промокода (считается на сервере)       |
| `POST /api/payments/yookassa/checkout`                            | `billing.checkout`, не support mode   | `{ courseId, promoCode? }` → `{ paymentId, confirmationUrl }`, веб переходит на ЮKassa     |
| `GET /api/payments/{id}/status`                                   | владелец платежа или `billing.manage` | статус для страницы возврата; пока платёж `pending`, API сам спрашивает ЮKassa             |
| `POST /api/payments/yookassa/webhook`                             | публичный (только IP ЮKassa)          | HTTP-уведомления ЮKassa                                                                    |
| `GET /api/payments`                                               | `billing.manage`                      | реестр платежей: фильтры `status`, `courseId`, `userId`, `search`, `from`, `to`, пагинация |
| `GET /api/payments/summary`                                       | `billing.manage`                      | итоги по тем же фильтрам: количество, получено, возвращено, итого                          |
| `GET /api/payments/export`                                        | `billing.manage`                      | CSV (UTF-8 с BOM, разделитель `;` — открывается в Excel с русской локалью)                 |
| `POST /api/payments/{id}/refund`                                  | `billing.manage`, не support mode     | полный возврат (остатка) через `POST /refunds` ЮKassa                                      |
| `GET/POST /api/promo-codes`, `PATCH/DELETE /api/promo-codes/{id}` | `billing.manage`                      | промокоды                                                                                  |

- Новые таблицы (миграции `0202_add_payments_and_promo_codes`, `0203_enable_payments_rls`, идут после
  `0201_add_phone_to_users`): `payments` и `promo_codes`. Обе с `tenant_id`, индексом по нему и
  RLS-политикой `*_tenant_isolation`, как остальные таблицы. Миграции только добавляют таблицы,
  существующие данные не меняются; API применяет миграции автоматически при старте.
- `payments`: пользователь, курс (+ название курса на момент покупки), сумма в копейках и валюта,
  исходная цена, скидка, промокод (id и код), провайдер, id платежа ЮKassa (уникальный), статус
  (`pending`/`succeeded`/`canceled`/`refunded`/`partially_refunded`), ссылка на оплату, ключ
  идемпотентности, e-mail для чека, даты создания/оплаты/отмены/возврата, сумма возврата.
- `promo_codes`: код (хранится в верхнем регистре, уникален в пределах школы — т. е. без учёта
  регистра), тип `percent`/`fixed`, значение (проценты 1–100 или копейки), необязательный курс, срок
  действия с/по, лимит активаций, счётчик активаций, флаг «активен».
- Успешная оплата записывает студента на курс тем же сервисом, что и обычная запись
  (`CourseService.enrollCourse`, с id платежа — статистика платных записей считается как раньше), и
  отправляет письмо «Оплата получена» на языке пользователя через существующую почтовую систему
  (шаблон `CoursePaymentSucceededEmail`, событие `CoursePaymentSucceededEvent` через outbox).
- Пока платёжный провайдер включён, записаться на платный курс кнопкой «Записаться» (эндпоинт
  `POST /api/course/enroll-course`) без оплаты нельзя — ответ 403 `payments.errors.paymentRequired`.
  Раньше это была дыра и для Stripe. Администраторы (`billing.manage`) и ручная запись студентов
  админом/группами работают как прежде.
- Если ЮKassa включена, все цены курсов сохраняются в рублях (`currency = rub`), выбор валюты по
  умолчанию в настройках организации скрыт.

**Веб (`apps/web`)**

- Страница курса: для платного курса вместо «Записаться» — «Купить за 1 500 ₽», ссылка «Есть
  промокод?» → поле + «Применить» (показывает старую цену и скидку) → переход на страницу ЮKassa.
- `/payment/return?paymentId=…` — страница возврата: опрашивает статус каждые 2,5 с; при успехе
  «Оплата прошла успешно» и переход на курс, при отмене — «Оплата не завершена» + «Попробовать
  снова», если через 90 с подтверждения нет — «Платёж ещё обрабатывается» + «Проверить ещё раз».
- Админка → Управление → «Платежи» (`/admin/payments`): фильтры (поиск по пользователю/e-mail/
  курсу/промокоду/ID платежа, статус, курс, даты с/по), итоги, таблица, «Выгрузить CSV», кнопка
  «Вернуть» с подтверждением.
- Админка → Управление → «Промокоды» (`/admin/promotion-codes`, то же место, что у Stripe): список,
  создание/изменение в диалоге, включение/выключение переключателем, удаление.
- Вкладка «Цена» в редакторе курса и все кнопки покупки показываются, если включён Stripe **или**
  ЮKassa (по `GET /api/payments/config`). Отдельного `VITE_`-флага нет — включение управляется только
  переменными API, пересборка веба не нужна.
- Тексты во всех 8 локалях (русский и английский полностью, остальные — английский текст).

## Переменные окружения (API, `.env.prd.api`)

| Переменная                  | Обязательна | По умолчанию  | Описание                                                                             |
| --------------------------- | ----------- | ------------- | ------------------------------------------------------------------------------------ |
| `YOOKASSA_SHOP_ID`          | да          | —             | shopId магазина из личного кабинета ЮKassa                                           |
| `YOOKASSA_SECRET_KEY`       | да          | —             | секретный ключ API (`live_…` в боевом магазине, `test_…` в тестовом)                 |
| `YOOKASSA_RECEIPT_ENABLED`  | нет         | `false`       | `true` — передавать данные чека по 54-ФЗ в платеже и возврате                        |
| `YOOKASSA_VAT_CODE`         | нет         | `1`           | код ставки НДС для позиции чека (`1` = без НДС), см. таблицу ниже                    |
| `YOOKASSA_TAX_SYSTEM_CODE`  | нет         | не передаётся | код системы налогообложения (1–6); нужен, если в магазине несколько СНО              |
| `YOOKASSA_WEBHOOK_IP_CHECK` | нет         | `true`        | проверять, что уведомление пришло с IP-адресов ЮKassa (`false` — только для отладки) |

Функция включена, только когда заданы и `YOOKASSA_SHOP_ID`, и `YOOKASSA_SECRET_KEY`. Некорректные
`YOOKASSA_VAT_CODE`/`YOOKASSA_TAX_SYSTEM_CODE` игнорируются (используется значение по умолчанию), а при
старте API пишет предупреждение `Invalid ЮKassa settings ignored…`. Один магазин на всю инсталляцию.

Пример для продакшена:

```dotenv
YOOKASSA_SHOP_ID=123456
YOOKASSA_SECRET_KEY=live_XXXXXXXXXXXXXXXXXXXXXXXXXXXX
YOOKASSA_RECEIPT_ENABLED=true
YOOKASSA_VAT_CODE=1
# YOOKASSA_TAX_SYSTEM_CODE=2
YOOKASSA_WEBHOOK_IP_CHECK=true
```

Секретный ключ не должен попадать в git, логи и переменные `VITE_*`.

## Настройка личного кабинета ЮKassa

1. Подключите магазин в <https://yookassa.ru> (договор, способы оплаты). Для отладки создайте
   **тестовый магазин** (в кабинете: переключатель магазинов → «Тестовый магазин») — у него свои
   shopId и секретный ключ `test_…`, деньги не списываются.
2. **shopId** — в разделе «Интеграция → Ключи API» (или в настройках магазина). Там же выпустите
   **секретный ключ** (при перевыпуске старый ключ перестаёт работать — сразу обновите `.env.prd.api`).
3. **HTTP-уведомления**: «Интеграция → HTTP-уведомления», URL
   `https://lms.wiki/api/payments/yookassa/webhook`, события:
   - `payment.succeeded` — обязательно;
   - `payment.canceled` — обязательно;
   - `refund.succeeded` — обязательно (частичные возвраты из кабинета ЮKassa тоже попадут в реестр);
   - `payment.waiting_for_capture` — не нужно (платежи создаются с `capture: true`; если такой статус
     всё же придёт, API подтвердит списание сам).
4. Проверка связки: создайте тестовый платёж на staging/проде с тестовыми ключами (см. чек-лист).
5. Тестовые карты: в тестовом магазине подходят карты из документации ЮKassa
   (<https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing>), например
   `5555 5555 5555 4477` — успешная оплата; срок действия — любая будущая дата, CVC — любые 3 цифры.
   Там же есть карты для отказа банка — ими удобно проверить сценарий «Оплата не завершена».
   Перед запуском сверяйтесь с актуальным списком в документации.

## Чеки по 54-ФЗ

- Если включить `YOOKASSA_RECEIPT_ENABLED=true`, в каждый платёж передаётся объект `receipt`:
  покупатель — e-mail пользователя из профиля, одна позиция — название курса (обрезается до 128
  символов), количество `1.00`, сумма к оплате (уже со скидкой), `vat_code` из `YOOKASSA_VAT_CODE`,
  `payment_subject: "service"`, `payment_mode: "full_payment"`, при необходимости `tax_system_code`.
  В возврат передаётся такой же чек на сумму возврата (чек возврата прихода).
- Чтобы чеки реально пробивались, в кабинете ЮKassa должно быть подключено одно из решений:
  **«Чеки от ЮKassa»** (облачная касса ЮKassa) или **своя онлайн-касса** партнёра (АТОЛ Онлайн,
  Бизнес.Ру, Orange Data и др.), настроенная в разделе «Настройки → Чеки». Без этого ЮKassa отклонит
  платёж с чеком — тогда либо подключите кассу, либо выключите `YOOKASSA_RECEIPT_ENABLED`.
- Если у пользователя в профиле некорректный e-mail, при включённых чеках оплата не начнётся
  (`payments.errors.receiptEmailRequired`) — чек некуда отправить.
- Коды ставки НДС (`vat_code`) по документации ЮKassa:

  | Код | Ставка           |
  | --- | ---------------- |
  | 1   | без НДС          |
  | 2   | 0%               |
  | 3   | 10%              |
  | 4   | 20%              |
  | 5   | расчётная 10/110 |
  | 6   | расчётная 20/120 |
  | 7   | 5% (УСН с НДС)   |
  | 8   | 7% (УСН с НДС)   |
  | 9   | расчётная 5/105  |
  | 10  | расчётная 7/107  |

  Переменная принимает значения 1–12; более новые коды (например, для ставок, введённых после
  изменений НК) берите из актуальной документации ЮKassa. Какой код и СНО указывать — решает
  бухгалтер.

- Коды СНО (`tax_system_code`): 1 — ОСН, 2 — УСН «доходы», 3 — УСН «доходы минус расходы», 4 — ЕНВД,
  5 — ЕСХН, 6 — патент. Передаётся только если задан.
- Для справки (не юридическая консультация):
  - Организации и ИП при онлайн-расчётах с физлицами по общему правилу применяют онлайн-кассу по
    54-ФЗ; исключения определяются законом и уточняются у бухгалтера.
  - Самозанятые (НПД) не применяют ККТ по 54-ФЗ — они формируют чеки в «Мой налог». Если магазин
    ЮKassa оформлен на самозанятого, оставьте `YOOKASSA_RECEIPT_ENABLED=false` и используйте механизм
    чеков для самозанятых, который предлагает ЮKassa.

## Возврат денег

1. Админка → Управление → «Платежи» → найдите платёж (поиск по e-mail, курсу или ID ЮKassa).
2. Кнопка «Вернуть» → в диалоге проверьте сумму, курс и e-mail → «Вернуть деньги».
3. API создаёт возврат остатка суммы (`POST /refunds` с ключом идемпотентности
   `refund-<id платежа>-<уже возвращённая сумма>` — двойной клик не приведёт к двойному возврату),
   затем перечитывает платёж в ЮKassa; статус становится «Возвращён». При включённых чеках
   ЮKassa пробивает чек возврата.
4. **Доступ к курсу не отзывается автоматически.** Если нужно — отпишите студента вручную (курс →
   «Записанные» → отписать).
5. Частичный возврат можно сделать в кабинете ЮKassa: по уведомлению `refund.succeeded` платёж в
   реестре получит статус «Частичный возврат» и сумму возврата; кнопка «Вернуть» после этого вернёт
   остаток.
6. Возврат возможен только для оплаченных платежей; деньги возвращаются на карту/счёт плательщика
   в сроки банка (обычно до нескольких рабочих дней).

## Безопасность

- **Тело уведомления не используется как источник истины.** Из уведомления берётся только id
  платежа ЮKassa. Если такого платежа нет в нашей БД — ответ 200 и предупреждение в логе (ЮKassa
  перестаёт повторять), к API ЮKassa не обращаемся. Иначе API запрашивает
  `GET /v3/payments/{id}` с ключами магазина и сверяет: id платежа, `metadata.paymentId` = id нашей
  записи, `metadata.tenantId` = школа записи, **сумма и валюта** = сумма и валюта записи. При любом
  расхождении изменения не применяются (в лог пишется причина, без персональных данных).
  Поддельный POST «payment.succeeded» ничего не даёт, пока ЮKassa сама не скажет, что платёж оплачен.
- **Проверка IP** (`YOOKASSA_WEBHOOK_IP_CHECK=true`): точная проверка по подсетям через
  `net.BlockList` для IPv4 и IPv6 — 185.71.76.0/27, 185.71.77.0/27, 77.75.153.0/25, 77.75.156.11,
  77.75.156.35, 77.75.154.128/25, 2a02:5180::/32. Никакого сравнения строк по префиксу. Чужой адрес → 403. За Traefik используется первое значение `X-Forwarded-For`; по умолчанию Traefik не доверяет
  заголовкам клиента и выставляет свой — не включайте `forwardedHeaders.insecure` для entrypoint'а
  без необходимости. Проверка IP — дополнительный барьер, основная защита — перезапрос платежа.
- **Идемпотентность.** Все переходы статусов — условные `UPDATE … WHERE status IN (…)`: повторные и
  одновременные уведомления (и опрос со страницы возврата) не приводят к повторной записи на курс,
  повторному увеличению счётчика промокода или второму письму. Сумма возврата только растёт.
  Отметка «оплачен», счётчик промокода и запись на курс выполняются в одной транзакции: если запись
  не удалась, всё откатывается, API отвечает 500, и ЮKassa повторит уведомление.
- **Цена считается только на сервере** (цена курса + проверка промокода); клиент передаёт лишь id
  курса и код. Ключ идемпотентности создания платежа — id нашей записи, повтор запроса не создаст
  второй платёж в ЮKassa. Повторное нажатие «Купить» в течение 30 минут возвращает ту же ссылку.
- **Мультитенантность.** Таблицы под RLS; вебхук не привязан к хосту школы — школа определяется по
  нашей записи о платеже и сверяется с `metadata.tenantId` из ответа ЮKassa.
- **Логи** содержат только id платежей, событие, итог и коды ошибок ЮKassa — без тел запросов,
  заголовков, e-mail, имён и ключей.
- Подтверждённый платёж, помеченный у нас отменённым (например, из-за таймаута при создании), всё
  равно засчитывается: деньги — источник истины.

## Чек-лист ручной проверки в продакшене

1. В `.env.prd.api` заданы `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` (сначала можно тестового
   магазина), при необходимости `YOOKASSA_RECEIPT_ENABLED=true` и `YOOKASSA_VAT_CODE`; контейнер `api`
   перезапущен. В логе при старте: `ЮKassa payments enabled (receipts: …, webhook IP check: on)`.
2. `curl https://lms.wiki/api/payments/config` → `{"data":{"provider":"yookassa","currency":"rub"}}`.
3. В БД появились таблицы `payments`, `promo_codes` (миграции 0202, 0203 применились без ошибок).
4. В кабинете ЮKassa настроены HTTP-уведомления на `https://lms.wiki/api/payments/yookassa/webhook`
   (`payment.succeeded`, `payment.canceled`, `refund.succeeded`).
5. Админ: курс → «Цена» → «Платный» → например 10 ₽ → «Сохранить»; курс опубликован. В админке
   появились пункты «Платежи» и «Промокоды».
6. Админ создаёт промокод `TEST50` (50%, только этот курс, лимит 1).
7. Тестовый студент (не записан на курс): на странице курса «Купить за 10 ₽» → «Есть промокод?» →
   `test50` → «Применить» → видна скидка → «Купить за 5 ₽» → страница ЮKassa.
8. Кнопка «Записаться» для платного курса не появляется; прямой вызов
   `POST /api/course/enroll-course` от студента отвечает 403.
9. Оплатить (в тестовом магазине — тестовой картой). После оплаты — возврат на
   `https://lms.wiki/payment/return?paymentId=…` → «Оплата прошла успешно» → переход на курс, курс
   открыт.
10. Пришло письмо «Оплата получена - <курс>»; при включённых чеках — чек от ЮKassa/кассы.
11. Админка → «Платежи»: платёж со статусом «Оплачен», суммой 5 ₽, скидкой и промокодом, ID ЮKassa
    совпадает с кабинетом; итоги посчитались; «Выгрузить CSV» открывается в Excel.
12. «Промокоды»: у `TEST50` «Использован 1 / 1»; повторная попытка применить — «Промокод уже
    использован максимальное число раз».
13. В кабинете ЮKassa → «HTTP-уведомления» → журнал: уведомление доставлено с ответом 200.
14. Отмена: начать оплату другим студентом и закрыть страницу ЮKassa/отказаться → через время статус
    «Отменён» (или «Платёж ещё обрабатывается» на странице возврата, пока ЮKassa не отменит платёж).
15. Возврат: «Платежи» → «Вернуть» → подтвердить → статус «Возвращён»; в кабинете ЮKassa возврат есть;
    при включённых чеках — чек возврата. Студент по-прежнему записан (отписать вручную при
    необходимости).
16. Поддельное уведомление:
    `curl -X POST https://lms.wiki/api/payments/yookassa/webhook -H 'Content-Type: application/json' -d '{"type":"notification","event":"payment.succeeded","object":{"id":"x"}}'`
    → 403 (адрес не ЮKassa); ничего не изменилось.
17. В логах API нет e-mail, имён, тел запросов и секретного ключа.
18. После проверки на тестовом магазине замените ключи на боевые (`live_…`), перезапустите `api`,
    повторите шаги 7–11 и 15 с реальной картой на минимальную сумму и верните платёж.

## Ограничения v1 и что дальше

- Рассрочка / «Оплата частями», подписки и рекуррентные платежи, сохранённые карты — не реализованы.
- Один магазин ЮKassa на инсталляцию (переменные окружения), без отдельных магазинов для школ.
- Счета и оплата для юрлиц (безнал по счёту) — не реализованы.
- Промокод на 100% не поддерживается (минимальная сумма платежа 1 ₽).
- Группа «после покупки» (автодобавление купившего в группу) не реализована — в LMS нет такой
  настройки курса.
- Лимит активаций промокода проверяется при оформлении; при одновременной оплате несколькими
  пользователями последнего «места» счётчик может превысить лимит на единицу.
- Возврат из админки — только полный (остатка); частичный — через кабинет ЮKassa.
